# 验证边界


## 自动检查

- `npm run check`：构建、Node 测试、文档链接。
- `npm run test:ui`：浏览器配置页交互与窄屏布局。
- `npm pack --dry-run`：打包内容检查。

测试覆盖：嵌套工具启用、保留 persona/注释/JS 标签、缺失工具追加、禁用分组、动态条件、幂等、版本冲突、只读预设、外部修改保护、精确还原、提示词开关持久化、安装失败和凭据输出不泄漏、并发操作拒绝。

浏览器测试覆盖：状态分离、显式预设选择、工具启用、提示词持久化、只读预设、冲突、连接失败、未知登录状态及移动布局。

真实 Host 验证和模型调用结果必须单独记录；模拟安装命令测试不能代表真实包安装，工具可见性不能代表 Codex/Claude 模型调用通过。

## 0.9.0 禁用与真实重装

20 项 Node/Host 测试、12 项浏览器测试通过。新增覆盖分别禁用、重新启用、保留另一个后端，以及包缺失时仍可禁用预设工具。

本机 DSH 0.1.6-alpha.1 的真实配置页验证：

1. 备份 Profile 和预设，通过 DSH CLI 卸载两个官方后端并重启，确认包不存在、宿主未注册、运行实例没有外部委派工具。
2. 分别点击 Smart Dev 的“安装并启用 Codex”和“安装并启用 Claude Code”，成功装回两个 0.1.5-rc.1 包并写入 Profile bundle。刷新状态后，当前宿主仍未注册，运行实例仍无工具。
3. 重启 DSH 后，两个后端均已注册，self-search Agent 可见 `subagent_codex` 和 `subagent_claude_code`。
4. 分别通过页面禁用两个工具：预设配置立即变为未启用，已加载 Agent 仍保留工具；重启后工具消失，而共享后端仍已安装并注册。
5. 通过页面重新启用两个工具并重启，恢复原有使用状态。

结论：在上述宿主版本中，安装后端和修改已加载预设的工具开关均需要重启 DSH 服务；刷新网页不足以生效。禁用只影响所选预设，不卸载后端包，也不表示取消正在执行的任务。此次未发送真实模型任务。
