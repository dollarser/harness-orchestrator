# ADR-002：执行策略由 Agent 决定

- 日期：2026-09-16
- 状态：接受，0.4.0 实现；真实模型端到端验收待完成
- 替代 ADR-001 中的固定流程、角色预算和验证门槛；保留 DSH 原生插件路线

## 背景

强制 Plan → Execute → Verify → Review 把任务策略固化成代码。用户必须维护跨项目验证命令，小改动也被迫规划和审查，修复次数受与任务无关的固定预算影响。用户明确要求让 Agent 自主决定规划、检查、修复和审查，只保留运行保障。

## 决策

每个命令交给一个 DSH 执行 Agent。提示说明任务与报告要求，不定义步骤序列；Agent 可以自行选择或跳过检查、追加修复和审查。删除 Plan/Review JSON 协议、独立验证执行端口、固定阶段和强模型/修复预算，不维护双模式。

保留模型选择、用户可选工具过滤、宿主权限、超时、取消、工作区并发锁、父会话 maintenance、子 Agent 清理和运行记录。允许脏工作区，以开始前快照记录原有工作。工具默认继承宿主，升级时保留用户已有过滤。

FINISHED 表示子 Agent 正常返回，原始报告描述任务结果。插件不根据主观文字推断 PASS，也不宣称独立检查通过。

## 取舍

- 减少角色调用和配置负担，适配不同项目和任务规模。
- 不再有强制独立审查、固定成本边界或机器验收门槛；质量依赖模型、工具和任务要求。
- 仍可由用户在任务或项目说明中要求特定检查，但插件不把这些要求编成固定状态机。
- 不把运行保障误当策略：取消与互斥必须可靠执行，不能依赖 Agent 自觉遵守。
- 作为开发自用工具，不保留旧流程配置兼容或迁移层；直接删除废弃字段。

## 验证

覆盖无检查任务正常返回、Agent 自述阻塞而不伪造验收结论、启动失败、截断/空响应、取消、超时、清理、拒绝废弃配置、脏工作区保留和设置页去除流程字段。真实模型自主决策质量仍需后续任务验收。

## 0.5.0 后续调整

取消 Git 根目录和首次提交前提，普通目录也可执行；快照只是可选证据。Backend 以标准选项和解释呈现，按模型归属传参。主 DSH Agent 的原生委派工具由预设启用，分工指引保持建议性质；/smart-dev 继续把任务委派给一个选定后端。
